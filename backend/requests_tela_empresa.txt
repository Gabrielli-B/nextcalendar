====================================================
  REGRAS DE NEGÓCIO — UC01 a UC06
====================================================

✅ termsAccepted deve ser TRUE para criar o establishment
✅ CNPJ é normalizado (remove pontuação) e validado (14 dígitos)
✅ CNPJ duplicado retorna 409 Conflict
✅ Trial de 30 dias iniciado automaticamente na criação
✅ Profile GESTOR criado automaticamente junto com o establishment
✅ CEP inválido retorna 422 Unprocessable Entity
✅ API de CEP indisponível → frontend envia street/city/state manualmente
✅ CNPJ não pode ser atualizado após o cadastro
✅ Delete é soft (campo active=false, não remove do banco)
✅ Validação de campos retorna 422 (UC06)
✅ Scheduler roda diariamente às 08:00 verificando trials

📌 CARD 9 — Verificar Status do Trial (UC05)
----------------------------------------------------
Endpoint : GET /establishments/{id}/trial
Exemplo  : GET http://localhost:8080/api/v1/establishments/uuid-do-establishment/trial

Resposta de sucesso (200):
{
  "establishmentId": "uuid-do-establishment",
  "trialStartDate": "2026-07-24T19:00:00",
  "trialEndDate": "2026-08-23T19:00:00",
  "daysRemaining": 30,
  "trialActive": true,
  "warningActive": false,
  "trialExpired": false
}

Campos:
  daysRemaining — dias restantes (0 se expirado)
  trialActive   — true enquanto dentro do período
  warningActive — true quando daysRemaining <= 7 (exibir banner de aviso)
  trialExpired  — true quando o trial venceu (bloquear funcionalidades premium)

Erros:
  404 — Estabelecimento não encontrado

Obs (scheduler automático):
  O backend verifica diariamente às 08:00 e:
  - Loga aviso para establishments com <= 7 dias restantes
  - Loga expirados para envio de e-mail de upgrade
  (integração com e-mail a implementar no módulo de notificações)
